# Demo voice end-to-end tests

Run the standalone benchmark on Linux with `TTS2MIC_BIN` and `PULSE_SERVER` set (normally supplied by the voice-devtools container), using its separate Playwright configuration and no test retries:

```sh
bunx playwright test --config apps/demo/e2e/voice/playwright.benchmark.config.ts
```

The app must already be running; prepare the fixed WAV fixtures as for the voice E2E suite. Set `VOICE_BENCHMARK_REPETITIONS` to an integer from 1 to 3 (default `1`) to repeat the fixed scenarios explicitly. Recorder and test time limits scale to the requested repetitions. The JSON and exactly two complete session WAVs are attached to the Playwright run; the ordinary voice E2E suite's per-turn audio artifacts remain unchanged. Captured active-audio duration is threshold-based non-silence, not VAD-ground-truth speech duration. Turn boundaries use the voice UI returning to connected/listening plus one second of quiet monitor audio; pauses may still make a boundary ambiguous. Latency is reported per human VAD segment using two complete session WAV attachments on one 48 kHz browser AudioContext/AudioWorklet clock: the human track is the actual injected `getUserMedia` microphone track used by the app, and the assistant track is the decoded `HTMLAudioElement`/WebRTC media-element output before the physical speaker sink. Both WAVs have the same frame range and sample rate; latency sample offsets address these files. Assistant latency is browser-rendered, not physical-speaker loopback. Voice-devtools VAD runs on the captured input WAV with threshold `0.9` and zero boundary padding; t=0 is the first VAD sample. Human VAD segments separated by no more than 500 ms are grouped as one turn. Assistant onset uses a `0.01` sample threshold and merges sub-10 ms quiet gaps. Overlap, unanswered turns, missing blocks, and unaligned frames are unsupported. The PulseAudio monitor remains a separate active-audio measure. UI state and monitor silence orchestrate scenario completion only, not latency. Barge-in overlap, reliable transcript word count, and WPM remain unsupported.

From the workspace root, run `bunx nx run @maelstrom-co/demo:voice-e2e`. Its TypeScript runner prepares three speech fixtures, launches the serial Chromium voice scenarios in the voice-devtools container, collects the HTML report and diagnostics under `apps/demo/dist/docker-voice`, and opens `report/index.html` on macOS. The Nx target is uncached and non-parallel. Docker orchestration uses the installed Docker CLI through Node's `child_process` API, so no Docker SDK dependency is required; the runner preserves a failing test exit status after collecting and opening the report.

Run the dedicated containerized benchmark from the workspace root with `bunx nx run @maelstrom-co/demo:voice-benchmark`. It uses the same voice-devtools image and fixture preparation but selects `playwright.benchmark.config.ts`, including its deterministic shared-AudioWorklet capture test; it does not change the ordinary voice E2E suite. The benchmark verifies that the image exposes `tts2mic-mcp vad` before running VAD. The host collects Playwright's HTML report, benchmark JSON/WAV attachments, runner metadata, and Docker log under `apps/demo/dist/docker-voice/` (`report/index.html` and `benchmark-results/`). Prerequisites are Docker, a running reachable demo app, and the voice-devtools audio container's Linux/PulseAudio/TTS2MIC setup. The host prepares all three WAV fixtures before launch; this needs the configured TTS provider's credentials unless matching audio is already cached (for ElevenLabs, `ELEVENLABS_API_KEY` and optionally `ELEVENLABS_VOICE_ID`). Local mode defaults to `http://localhost:3000` and the configured WebSocket port; `MAELSTROM_HOST`, `MAELSTROM_APP_PORT`, and `MAELSTROM_WS_PORT` can configure host forwarding. For a BYOK target, provide `MAELSTROM_E2E_OPENAI_API_KEY` in the host shell; it is passed only into the benchmark container when present and is never printed by the runner. Set `VOICE_BENCHMARK_REPETITIONS` to 1–3 (default 1). Do not pass provider secrets such as `DEEPGRAM_API_KEY` to the audio container. Benchmark retry count remains zero. The benchmark's active-audio duration and turn boundary are approximate; human-first-input latency, barge-in, transcript word count, and WPM remain unsupported.

By default, tests target the local app at `http://localhost:3000` (or the documented `MAELSTROM_HOST` forwarding host); start the local server-key demo with `bun --cwd apps/demo run dev`. Unset or empty `MAELSTROM_BASE_URL` selects this local mode, preserving `MAELSTROM_APP_PORT`/`MAELSTROM_WS_PORT` forwarding and local readiness checks. To target a hosted deployment instead, set `MAELSTROM_BASE_URL` to its HTTP(S) URL, for example `MAELSTROM_BASE_URL=https://demo.maelstrom-ai.co/ bunx nx run @maelstrom-co/demo:voice-e2e`. Remote mode checks that URL and uses it as Playwright's browser base URL; it does not inspect or forward local app ports. No API key is needed for local server-key mode. If ports 3000/3001 belong to another checkout, run this checkout's servers separately, without stopping that checkout:

```sh
WS_PORT=3011 bun --cwd apps/demo run dev:ws
VITE_WS_URL=ws://localhost:3001 bunx nx run @maelstrom-co/demo:serve --host=0.0.0.0 --port=3010
MAELSTROM_APP_PORT=3010 MAELSTROM_WS_PORT=3011 bunx nx run @maelstrom-co/demo:voice-e2e
```

The container forwards those host ports to Chromium on localhost:3000/3001. Local server-key mode does not require an E2E key. Each test creates its own browser context and page, navigates to the configured target URL (including path and query), and verifies the public seed contains `calendar-main` and `tasks-main` plus the voice controls. The clean page creates a fresh workspace/voice/conversation session without a product reset action or test-only endpoint. Hosted deployment seed/configuration is not verified by this local setup.

For a hosted or other BYOK deployment, export `MAELSTROM_E2E_OPENAI_API_KEY` in the shell that runs the Nx target. The worker reads the value once into process memory; each isolated test page re-enters it through the actual password-masked drawer UI using DOM setter/input events (never a secret-valued Playwright fill action), scoped to the popup's `Add key` or `Save` button. If the app requires BYOK and the variable is absent, setup fails with an actionable message. Never place the key in repository files, fixture text, command-line arguments, logs, reports, traces, or artifacts. Hosted browser execution and the currently deployed target's configuration remain unverified.

`TTS_PROVIDER`, `ELEVENLABS_API_KEY`, and `ELEVENLABS_VOICE_ID` are needed only to regenerate deterministic-named speech fixtures. TTS responses are cached on the host and reused across fixture-generation runs. By default the cache is `$XDG_CACHE_HOME/tts2mic-mcp` when `XDG_CACHE_HOME` is set, otherwise `$HOME/.cache/tts2mic-mcp`. Set `MAELSTROM_TTS_CACHE_DIR` to an alternate host directory; relative overrides resolve from the current working directory. The resolved directory must be writable and outside the repository; an in-repository path is rejected, including when reached through a symlink. The directory is created if needed. To clear the default cache, remove that directory (or remove the configured override directory) when no test run is using it. Cache identity includes provider, language, voice, text hash, and output format where supported, but ElevenLabs cache identity does not include model ID; switching models may therefore reuse audio cached for another model. Generated speech persists outside the repository and may be sensitive; protect the cache accordingly and clear it when no longer needed.

The report attaches both input WAVs and per-turn captured output WAVs for each scenario, plus existing session audio, screenshots, protocol projection, and recorder diagnostics. Playwright traces are disabled because a trace may capture password-input events. Failure screenshots remain enabled; the key drawer uses a password input. Protocol evidence projects only chart layout identifiers and excludes credentials, transcript/intention text, vessel definitions, and auth payloads.
