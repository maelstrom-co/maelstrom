# Prompt evaluation CLI

The registry names five cases: `onboarding-implementation`, `modeling-read-only`, `react-inventory`, `react-conversion`, and `debugging-read-only`. The modeling task uses the registered case input and evidence grader; the older direct modeling API remains available for compatibility. Inputs keep canonical prompt bodies and versions, add case-specific task text and fixture bytes, and record hashes. Evidence tasks publish an exact JSON schema, literal fixture paths, 4–300 Unicode-code-point quote bounds, and exact substring rules. Read-only cases grade process/transport, JSON schema, fixture paths, quote length/membership, and zero filesystem changes with separate diagnostics. Those objective checks are not semantic correctness: semantic review remains `unrun` until independent review.

No model call runs as part of CI. Pi, OpenCode, and Claude Code adapters support the five registered cases; the generic `command` adapter remains available for literal argv. OpenCode uses a unique per-process primary agent with a final wildcard-deny permission rule; source inspection shows agent rules are appended after global permission rules, and the CLI emits a fallback warning if the selected agent is invalid. Two earlier attempts using only the global overlay are retained as invalid/noisy evidence: one completed `task` tool calls. A later harmless smoke used the corrected profile but stopped at an API HTTP 400 before a final answer; therefore the corrected profile's no-tools behavior is source-backed, not confirmed by a successful live response. An offline `opencode --pure agent list` check showed the generated agent is present and primary. Do not infer isolation from cwd or `--pure`. Read-only cases default to tools disabled and include supplied fixture context. This checks context-only output, not repository-tool use or read-only obedience. Requested tool policy and effective inherited configuration are recorded separately; these CLIs do not provide an OS sandbox. Pi disables sessions, extensions, skills, prompt templates, themes, and context-file loading, but user/global Pi settings still apply. OpenCode merges a unique primary agent into the inherited child-only `OPENCODE_CONFIG_CONTENT`, preserving other inline JSON/JSONC model, provider, endpoint, and agent settings; its own permission rules deny tools, alongside `OPENCODE_PERMISSION` and `--pure` (external plugins only). Global/project instructions, other config, hooks, and MCP state remain in scope. The selected agent has no model override, which may differ from an operator's default-agent-specific model. Claude Code's live adapter remains untested because `claude` is not installed here. Claude Code passes `--tools ""`, denies MCP tools, and uses `dontAsk`; hooks/settings may still apply. Do not interpret cwd as confinement.

## Deterministic implementation grading

`gradeCandidate` checks an already-produced candidate and **never starts an agent**. It is separate from execution authorization, but typecheck/tests/browser checks execute candidate code on the trusted host; it is not safe isolation for arbitrary hostile source. Use only approved disposable trial candidates. Onboarding and React-conversion candidates are checked against copied trusted baselines, an application TypeScript allowlist, local SDK typecheck, evaluator-owned React behavior tests where applicable, and a real Playwright browser check. The browser grader injects a temporary evaluator observer at the public SDK Orchestrator connection seam, correlates evaluator-observed registrations and instance-to-Vessel mappings with rendered markers without requiring particular ID names, then checks marker geometry and case-specific UI. Calibration includes known-good onboarding and conversion candidates whose Vessel/instance IDs differ from the base variants. Only named disposable outputs (`.vite/`, `node_modules/.vite/`, `dist/`, `coverage/`, `test-results/`, `playwright-report/`) may be added, modified, or deleted; symlinks, dependencies outside the named Vite cache, source/config and protected support/baseline changes are not exempt. Integrity/allowlist failures block executable checks. A simulated connector is only local test infrastructure; neither the evaluator nor a report may describe it as live Engine verification. Semantic review stays explicitly `unrun`.

After `bun apps/docs/prompts/acceptance/prepare-trials.mjs`, use the prepared private disposable project path printed by the script. Calibrate the grader without model calls using known-good and deliberately broken candidates:

```sh
bun apps/docs/prompts/evaluation/calibrate-cases.ts /private/tmp/PREPARED_TRIAL_ROOT
```

Calibration separately verifies immutable source/config/support files byte-for-byte and checks the package manifest against the documented prepared-fixture transformation (pinned dependencies and local SDK archives); it refuses a modified tree. It exits nonzero if a known-good app (including onboarding and conversion variants with renamed Vessel/instance IDs) fails SDK/browser/UI checks, or a known-bad SDK, collapsed/hidden/unregistered Chart, no-SDK DOM lookalike, missing/wrong ticket status, whitespace/pending/controlled/error/success/handler regression, or tampered baseline test is accepted. A dedicated known-good conversion probe runs `bun run build` and `bun run test` with an old hashed asset already in `dist/`, then invokes production `gradeCandidate` against the pre-check baseline; calibration requires observing that asset's deletion, new hashed JS/CSS output, and a passed allowlist. The probe restores `dist/`, the source overlay, and the local Vite cache before later calibration cases. The browser context grants `local-network-access` only to its loopback Vite origin so Chromium can receive the optimizer/HMR reload; it does not grant remote origins. Keep the prepared tree and logs private.

Implementation agent execution is a separate, explicit opt-in. The authorization below means trusted-host tools are allowed by the operator; **it does not create OS confinement**. Use only disposable prepared trial projects, never a workspace checkout. Each task carries strict instructions to stay in its own project and avoid credentials, environment/config, network, unrelated processes, and delegation, but those are instructions, not a technical security boundary. Candidate graders do not require this authorization.

```sh
bun run --cwd apps/docs prompts:evaluate --case onboarding-implementation --runner pi \
  --candidate-root /private/tmp/PREPARED_TRIAL_ROOT/onboarding \
  --authorize-coding operator-approved --pi-tools enabled \
  --output /private/tmp/maelstrom-onboarding-evaluation
```

For a read-only case, omit candidate/authorization/tool flags; Pi and Claude Code default to their requested tools-disabled profiles:

```sh
bun run --cwd apps/docs prompts:evaluate --case modeling-read-only --runner pi --output /private/tmp/maelstrom-pi-modeling
bun run --cwd apps/docs prompts:evaluate --case react-inventory --runner claude --output /private/tmp/maelstrom-claude-inventory
bun run --cwd apps/docs prompts:evaluate --case modeling-read-only --runner opencode --output /private/tmp/maelstrom-opencode-modeling
```

OpenCode 1.18.32 uses `run --format json`, reads prompt text from stdin, and reports JSONL text/step events; the parser requires a complete final `stop` step and matching text, zero exit, no error event, and a single session. Protocol and permission precedence follow the [v1.18.32 tagged CLI source](https://github.com/anomalyco/opencode/tree/545f51d/packages/opencode/src). Its JSON does not establish model/provider identity. A unique primary agent supplied through child-only `OPENCODE_CONFIG_CONTENT` places wildcard denials after inherited permissions; the agent contains no model override and is selected explicitly. The earlier smoke used only a global permission overlay, which source inspection showed could be overridden by an agent-specific allow. `--pure` suppresses external plugins, not project/global config or instructions. Global/project instructions, hooks, and MCP configuration may still load; no OS isolation is provided. Claude Code uses `-p --output-format json`, `--tools ""`, and `--disallowedTools mcp__*`; its result envelope must be successful and nonempty. Its normal config/hooks may still apply. Install and authenticate CLIs yourself before use; the evaluator never installs, logs in, or edits user configuration and does not pass an explicit model override. OpenCode's temporary named agent may not inherit a model configured only on the operator's default agent, so verify that profile choice deliberately; the evaluator records runtime identity as unknown unless observed. Version discovery is bounded; unknown means probe failed or was unavailable.

Implementation remains explicit opt-in and requires a prepared disposable candidate and execution authorization. Managed Pi/OpenCode/Claude adapters additionally require `--tools enabled`; generic commands use caller-defined literal argv and retain unknown tool policy:

```sh
bun run --cwd apps/docs prompts:evaluate --case onboarding-implementation --runner claude \
  --candidate-root /private/tmp/PREPARED_TRIAL_ROOT/onboarding \
  --authorize-coding operator-approved --tools enabled \
  --output /private/tmp/maelstrom-claude-onboarding
```

The Pi spelling `--pi-tools enabled|disabled` remains an alias for `--tools`; conflicting values are rejected. Generic argv-based CLI policy remains unknown. `PI_CLI`, `OPENCODE_CLI`, and `CLAUDE_CLI` can select executables for testing. Tool-enabled runs are trusted-host execution, not OS confinement, and may run candidate checks. Never run live Engine/provider/voice calls for these fixtures.

Output directories are created mode `0700` with files mode `0600`, outside the checkout. Raw CLI JSONL/stdout and stderr may contain sensitive content and must remain private. The manifest records the selected runner, actual version, model/provider/session only when observed (otherwise `unknown`), transport and process status, requested tool policy versus its limits, candidate diff/check results, and explicitly states the trust boundary. Candidate grader command argv/status/exit/timeout/cancellation/duration and the last 2,000 characters of combined process evidence (including browser geometry/SDK output or failure diagnostics) are also retained in that private manifest. Subprocess output is capped per stream; incomplete/truncated capture is reported rather than silently treated as complete. Do not put credentials, raw output, or the prepared candidates in the repository or handoff.

This is not a hosted Engine, SDK, skill-comparison, or model-benchmark harness. No commits, bookmarks, pushes, user/global settings changes, or repository history changes are performed.
