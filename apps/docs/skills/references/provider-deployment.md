# Provider selection and deployment

Select provider and deployment only from the user's goal and available evidence. Maelstrom's current voice documentation describes specific supported paths, including OpenAI Realtime and LiveKit Cascade. Do not imply support for an unspecified provider or install voice packages before the decision justifies them.

Keep long-lived provider keys out of browser code. Place each key only in its owning server or worker process: provider minters and token endpoints use the keys they need, and the supported LiveKit cascade worker holds its required LiveKit, Deepgram, and Cartesia credentials. A short-lived, narrowly scoped Grant may cross to the browser only when required by the selected provider's documented flow. The application's server endpoint must independently enforce caller authentication, authorization, origin policy, and rate limits; a package Minter does not authenticate the caller. Never give a worker Vessel/Chart structure or make server/worker packages depend on browser packages.

Use the selected provider's setup guide and deployment requirements: [OpenAI Realtime](https://docs.maelstrom-ai.co/guides/voice/openai-realtime/) or [LiveKit cascade](https://docs.maelstrom-ai.co/guides/voice/livekit-cascade/). Treat those external pages as version-specific only when their version matches the installed SDK; otherwise label them as current, unversioned guidance and verify APIs against installed exports, types, source, and tests. The downloaded bundle supplies the exact [voice architecture](canonical-voice/docs/realtime-voice-architecture.md) and [general architecture](canonical-voice/docs/architecture.md). Read their provider package contracts and credential boundaries before implementation; no consumer checkout or private decision record is required. Keep provider differences visible. State exact package versions, deployment assumptions, and which credential, microphone, network, and Engine checks were or were not performed. Never expose real credentials in test fixtures or reports.
