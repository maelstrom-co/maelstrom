# Realtime lifecycle and turn-taking

Keep voice optional and provider behavior explicit. Inspect the selected adapter's actual exports, lifecycle, and provider guide. A speech-native provider owns speech recognition, model, speech synthesis, and turn detection behind one connection; a cascade provider supplies transport while speech services run server-side. Do not flatten these distinct flows into a fictional common API.

Turn Mode—automatic turn-boundary detection or user-delimited turns—is runtime behavior of a live connection, not a fixed provider property. Observe and handle the supported runtime mode. Manage session connect/disconnect, cancellation, expiry/refresh, and teardown according to the selected adapter's evidenced contract; avoid claiming automatic reconnection unless documented and tested.

Speech supplies natural-language intent. The Engine remains the planner using client-owned Chart state. Voice UI is not automatically a Vessel. Read the exact bundled [realtime voice architecture](canonical-voice/docs/realtime-voice-architecture.md), [general architecture](canonical-voice/docs/architecture.md), and [provider taxonomy ADR](canonical-voice/docs/adr/0001-realtime-providers-come-in-two-kinds.md), [credential-custody ADR](canonical-voice/docs/adr/0002-credential-custody-is-a-dependency-edge.md), and [turn-taking ADR](canonical-voice/docs/adr/0003-turn-taking-is-provider-neutral.md). The [public voice boundary guide](https://docs.maelstrom-ai.co/understanding/voice-architecture/) is useful runtime context; it is not a substitute for the included canonical ADRs. Verify version-specific behavior locally; a source review is not a microphone/provider test.
