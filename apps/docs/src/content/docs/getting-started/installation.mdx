Maelstrom is distributed as scoped packages so you can install only the layers your app needs. Most React apps start with `@maelstrom-co/react` in the browser and `@maelstrom-co/engine` on the server.

## Packages

| Package | Purpose |
|---------|---------|
| `@maelstrom-co/react` | React bindings — `createMaelstrom()`, `vessel()`, hooks, Provider, Chart |
| `@maelstrom-co/client` | Framework-agnostic client — Orchestrator, connectors, managers |
| `@maelstrom-co/protocol` | Shared types, Zod schemas, message definitions |
| `@maelstrom-co/engine` | Server-side LLM decision engine |

## Minimal installs by use case

| Use case | Install in the browser app | Install on the server |
| --- | --- | --- |
| React chart only | `@maelstrom-co/react` | An engine implementation, commonly `@maelstrom-co/engine` |
| Framework-agnostic client | `@maelstrom-co/client @maelstrom-co/protocol` | An engine implementation |

`@maelstrom-co/react` depends on the client and protocol packages, but many guides install `@maelstrom-co/client` explicitly because connector classes such as `WebSocketConnector` are imported from the client package. Keeping that dependency explicit makes the transport boundary visible in your app.

## Install

<Tabs>
  <TabItem label="npm">
  ```bash
  # Client-side React app
  npm install @maelstrom-co/react @maelstrom-co/client

  # Server-side reference engine
  npm install @maelstrom-co/engine
  ```
  </TabItem>
  <TabItem label="bun">
  ```bash
  # Client-side React app
  bun add @maelstrom-co/react @maelstrom-co/client

  # Server-side reference engine
  bun add @maelstrom-co/engine
  ```
  </TabItem>
  <TabItem label="pnpm">
  ```bash
  # Client-side React app
  pnpm add @maelstrom-co/react @maelstrom-co/client

  # Server-side reference engine
  pnpm add @maelstrom-co/engine
  ```
  </TabItem>
</Tabs>

## Peer dependencies

`@maelstrom-co/react` requires:

- `react` >= 18.0.0
- `react-dom` >= 18.0.0

## Environment variables

The reference Engine requires an LLM provider API key. Only one provider key is needed for a basic setup:

```bash
# .env
GOOGLE_GENERATIVE_AI_API_KEY=your-key  # Google Gemini
OPENAI_API_KEY=your-key                # OpenAI
ANTHROPIC_API_KEY=your-key             # Anthropic Claude
```

<Aside type="tip">
  Choose one provider first. You can switch providers later by changing the engine adapter; see [Use a custom LLM provider](/guides/engine/custom-llm-providers/).
</Aside>
