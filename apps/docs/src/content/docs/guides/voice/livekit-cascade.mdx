The LiveKit cascade adds browser-controlled voice without adding another planning model. `LiveKitAdapter` detects turns automatically by default and exposes `turnControl` only in manual mode. A worker transcribes speech with Deepgram and synthesizes settled results with Cartesia, while the browser sends each final transcript through `RealtimeSession` as ordinary `update_ui` intent.

You mint a room grant on your server, run a model-free worker, connect the browser adapter, then harden the route before it ships. New to the cascade? [Run the voice demo locally](/tutorials/run-voice-locally/) first.

## Before you start

Provide:

- a Maelstrom React instance with its normal Engine Connector
- a LiveKit server and credentials for the token service and worker
- Deepgram and Cartesia credentials for the worker
- a secure browser context with microphone permission
- the `@maelstrom-co/realtime-livekit`, `@maelstrom-co/realtime-livekit-server`, `@maelstrom-co/realtime-livekit-agent`, and `@maelstrom-co/react-realtime` packages

<Aside type="danger" title="Read these before you write any code">
  **LiveKit signing credentials stay on the server.** `LIVEKIT_API_KEY` and
  `LIVEKIT_API_SECRET` sign short-lived room grants and never reach browser
  code. Deepgram and Cartesia keys belong to the worker process alone.

**The minter does not authenticate callers.** Your server must authenticate
the request and derive room and participant scope. The browser never chooses
its own room or identity.

**The worker holds no planning model.** It runs STT and TTS only, receives no
Vessel, Chart, or grounding context, and
`LiveKitAdapter.injectGrounding()` is intentionally a no-op.

</Aside>

## What you own

The cascade splits into three roles you deploy, arranged around a LiveKit room. Each role has its own lifecycle and credential boundary.

<OwnershipDiagram

/>

Audio reaches the room without crossing your application server, so the mint route can end after each request. Nothing joins the worker to the Engine: the worker publishes a final transcript to the room, the browser adapter turns it into ordinary intent through `RealtimeSession`, and the Engine plans against the client-built Chart snapshot exactly as it does for typed intent.

Routing the transcript through the browser also decides when the worker speaks. A successful UI update waits for rendering to settle before the result returns through LiveKit for TTS. Malformed tool arguments and genuine submission failures return immediately.

One automatic turn goes: browser VAD → LiveKit room → worker STT → final transcript → `update_ui` intent → Engine → settled UI → worker TTS. [Voice architecture: cascade vs realtime](/understanding/voice-architecture/) walks each stage.

## Mint a room grant on your server

Create an authenticated endpoint that derives room scope and signs a grant. Keep LiveKit signing credentials in server-only code.

```ts title="server/livekit-token.ts" {1-5,8,13-16}
import { isOk } from "@maelstrom-co/protocol";
import {
  mintFailureHttpStatus,
  mintLiveKitToken,
} from "@maelstrom-co/realtime-livekit-server";

export async function POST(request: Request): Promise<Response> {
  const authenticated = await requireAuthenticatedVoiceSession(request);
  if (authenticated === null) {
    return Response.json({ error: "unauthorized" }, { status: 401 });
  }

  const result = await mintLiveKitToken({
    roomName: authenticated.roomName,
    identity: authenticated.identity,
  });
  if (!isOk(result)) {
    return Response.json(
      { error: "mint-failed" },
      { status: mintFailureHttpStatus(result.error.reason) },
    );
  }

  return Response.json(result.value, {
    headers: { "Cache-Control": "private, no-store" },
  });
}
```

`requireAuthenticatedVoiceSession` is application code, not a Maelstrom export. It must deny unauthorized callers, bind the principal to a server-side session, and derive `roomName` and `identity` from that trusted session. The browser sends neither value.

The server process requires `LIVEKIT_URL`, `LIVEKIT_API_KEY`, and `LIVEKIT_API_SECRET`. `LIVEKIT_TOKEN_TTL` is optional and defaults to `15m`. Unsupported or unsafe values fail closed as `invalid-config`.

<Aside type="danger" title="Repository demo route is development-only">
  The checked-in demo mint route lacks production authentication, trusted scope
  derivation, and explicit no-store headers. Do not deploy it.
</Aside>

## Fetch the grant in the browser

Fetch the grant with same-origin credentials and a CSRF proof, then validate the unknown response before connecting:

```ts title="src/voice/livekit-token.ts" {1-4,17}
import {
  type LiveKitTokenGrant,
  LiveKitTokenGrantSchema,
} from "@maelstrom-co/realtime-livekit/token";

export async function fetchAuthenticatedLiveKitToken(): Promise<LiveKitTokenGrant> {
  const response = await fetch("/api/livekit-token", {
    method: "POST",
    credentials: "same-origin",
    headers: { "X-CSRF-Token": getCsrfToken() },
  });

  if (!response.ok) {
    throw new Error(`LiveKit token mint failed with status ${response.status}`);
  }

  return LiveKitTokenGrantSchema.parse(await response.json());
}
```

The schema requires a non-empty token, a `ws:` or `wss:` LiveKit URL, and an absolute Unix expiry. Shape validation does not replace endpoint authentication or authorization.

## Start the STT/TTS worker

Run the model-free worker as a separate long-running process. It holds LiveKit and speech-provider credentials but no planning LLM and no UI grounding.

```ts title="voice-worker.ts"
import { runVoiceAgent } from "@maelstrom-co/realtime-livekit-agent";

runVoiceAgent();
```

```bash
node --env-file=.env voice-worker.ts start
```

Keep environment values grouped by process:

| Process        | Required environment                                                                           | Optional environment                              |
| -------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| Token endpoint | `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`                                         | `LIVEKIT_TOKEN_TTL` (default `15m`)               |
| Agent worker   | `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `DEEPGRAM_API_KEY`, `CARTESIA_API_KEY` | `MAELSTROM_STT_FLUSH_TIMEOUT_MS` (default `2000`) |
| Browser        | None of these secrets                                                                          | None                                              |

## Connect the browser adapter

Create one adapter per Maelstrom voice session. Authenticated server policy and the signed grant remain authoritative for the actual room and participant.

```ts title="src/maelstrom.ts"
import { createMaelstrom } from "@maelstrom-co/react";
import {
  type CreateAdapterContext,
  maelstromRealtime,
} from "@maelstrom-co/react-realtime";
import { LiveKitAdapter } from "@maelstrom-co/realtime-livekit";
import { fetchAuthenticatedLiveKitToken } from "./voice/livekit-token";
import { vessels } from "./vessels";

export const m = createMaelstrom({ vessels }).with(
  maelstromRealtime({
    createAdapter: ({ sessionId }: CreateAdapterContext) =>
      new LiveKitAdapter({
        roomName: `maelstrom-${sessionId}`,
        mintToken: (_roomName) => fetchAuthenticatedLiveKitToken(),
      }),
  }),
);
```

During `connect()`, the adapter acquires a local microphone track, creates the local streams needed for metering and VAD, publishes an upstream-gated track, and pauses publication before automatic or manual mode becomes visible. A denied permission surfaces as `MIC_PERMISSION_DENIED`; explain how to allow access, then reconnect.

## Configure browser VAD

Leaving the `vad` property out of the options object passed to `new LiveKitAdapter(...)` enables default automatic mode. `vad: true` does the same, while an object keeps automatic mode and customizes it:

```ts
new LiveKitAdapter({ mintToken, roomName }); // `vad` omitted
new LiveKitAdapter({ mintToken, roomName, vad: true });
new LiveKitAdapter({ mintToken, roomName, vad: { preRollMs: 300 } });
new LiveKitAdapter({ mintToken, roomName, vad: false });
```

Automatic mode uses `/vad-web/`, retains `250` milliseconds of transport pre-roll, and otherwise uses provider defaults. Copy the package-matched VAD and ONNX Runtime assets into that public directory:

```bash
maelstrom-livekit-assets public/vad-web
```

Run the copy before each build:

```json
{
  "scripts": {
    "prepare:voice-assets": "maelstrom-livekit-assets public/vad-web",
    "build": "bun run prepare:voice-assets && vite build"
  }
}
```

Set `vad: false` only for intentional manual mode. Safe automatic-mode failures also expose manual controls through `useVoice()`. Automatic mode keeps idle microphone media local and opens LiveKit publication only for accepted speech.

[Browser VAD and barge-in](/understanding/browser-vad-and-barge-in/) documents supported tuning, asset hosting and CSP, transport pre-roll, serialization, safe degradation, and fatal transport failures.

## Delimit each manual turn

Render manual controls only while `turnControl` is available. Call `startTurn()` on press and `endTurn()` on every release or cancellation path:

```ts title="src/voice/manual-turn.ts"
export async function runManualTurn(
  turnControl: AdapterTurnControl,
): Promise<void> {
  await turnControl.startTurn();
  try {
    await waitForRelease();
  } finally {
    await turnControl.endTurn();
  }
}
```

`turnControl` is dynamic. Healthy automatic mode leaves it undefined. It appears after intentional `vad: false` configuration or after an automatic-mode failure has safely paused upstream publication. Serialize operations so a release cannot overtake a pending start, and end the turn on pointer cancellation, focus loss, a hidden document, disconnect, and unmount.

## Show session state

Render lifecycle state, transcripts, and actionable recovery beside the voice control. `turnModeError` distinguishes intentional manual mode from safe automatic degradation:

```tsx title="src/VoiceStatus.tsx"
export function VoiceStatus() {
  const {
    state,
    error,
    userTranscript,
    assistantTranscript,
    turnMode,
    turnModeError,
  } = m.useVoice();
  const degraded = turnMode === "manual" && turnModeError !== undefined;

  return (
    <section aria-label="Voice status">
      <p>{state}</p>
      {degraded && (
        <p role="status">
          Automatic voice detection is unavailable. Hold to talk instead.
        </p>
      )}
      {userTranscript && <p>You: {userTranscript.text}</p>}
      {assistantTranscript && <p>Assistant: {assistantTranscript.text}</p>}
      {error !== undefined && (
        <p role="alert">Voice stopped. Start voice again to reconnect.</p>
      )}
    </section>
  );
}
```

Never render `turnModeError`, raw error messages, stacks, or causes. They can contain room tokens or provider details. Use typed state for fixed recovery copy and send diagnostics through a redacted telemetry boundary.

## Verify

Check automatic VAD, manual fallback, and a complete turn across all three roles:

- **Token route:** an authenticated request passes origin, CSRF, and rate-limit controls; the grant validates and every response carries `Cache-Control: private, no-store`.
- **Browser:** the session reaches `connected`; idle automatic mode sends no upstream microphone media; accepted speech sends pre-roll once; intentional `vad: false` starts in manual mode.
- **Safe fallback:** a recoverable VAD failure pauses upstream publication before manual controls appear. A failure that cannot stop upstream media tears down the session instead.
- **Worker:** the worker joins the authorized room and publishes one final transcript for an accepted turn.
- **Lifecycle:** the transcript becomes ordinary intent, the UI settles, and TTS follows settle rather than predicting the result.

## Harden the mint route

Before exposing the route to the internet, add each control below. All policy failures must deny the request.

| Control                              | Without it                                                      |
| ------------------------------------ | --------------------------------------------------------------- |
| Exact-origin allowlist               | Another site can drive a browser to mint rooms on your account. |
| CSRF proof bound to the session      | A logged-in browser mints on an attacker's behalf.              |
| Shared rate limit keyed by principal | One compromised account creates rooms without bound.            |
| Server-derived room and identity     | The browser joins another user's room.                          |
| Short token lifetime                 | A leaked grant remains useful longer than necessary.            |
| `Cache-Control: private, no-store`   | A cache can retain a bearer room token.                         |
| Maximum active-session duration      | An abandoned session keeps consuming provider resources.        |
| Redacted failure telemetry           | Logs expose room tokens or provider credentials.                |

Token TTL does not bound an active session. Enforce duration separately, call `disconnect()` on policy termination, and clean up abandoned rooms and participants.

Treat the VAD asset directory as trusted executable infrastructure. Never derive it from user input; use credential-free HTTPS for cross-origin assets, immutable versioned paths, explicit CORS, correct JavaScript/WebAssembly/model content types, and a CSP that supports the required worklets.

## Recover from failures

| Failure                                 | Recovery                                                                                                |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Token request or grant validation fails | Keep voice disconnected and correct caller policy or server configuration before retrying.              |
| Microphone permission is denied         | Explain how to allow access, then reconnect.                                                            |
| Automatic VAD degrades safely           | Show fixed hold-to-talk guidance and use the dynamic manual control.                                    |
| Upstream publication cannot be paused   | Treat the failure as fatal; do not advertise manual fallback.                                           |
| Worker does not answer                  | Check the worker, LiveKit connectivity, and speech-provider keys; do not move planning into the worker. |
| TTS fails after rendering               | Keep the session usable and report that spoken confirmation was lost; the UI result already applied.    |

## What you get without asking

**Speak-after-render.** Each final transcript becomes one `update_ui` call. For a successful UI update, `RealtimeSession` waits for rendering to settle before it calls `sendToolResult()`. Cartesia therefore speaks the rendered result rather than a prediction.

**A worker that cannot plan.** The worker has no model session to ground. Do not forward Chart structure or Vessel domain data to it.
