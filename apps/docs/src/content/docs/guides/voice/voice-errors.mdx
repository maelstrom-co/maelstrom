This page is for client code that needs to render recoverable voice failures without learning every provider's private error shape. The voice runtime keeps one public event name and adds optional metadata when an STT or TTS provider failure can be classified.

This page documents the error contract used by the voice runtime and demo websocket bridge.

## Voice error contract

The demo voice websocket keeps the existing `engine.error` event name.

For generic setup or runtime failures, the payload stays in the legacy shape:

```ts
{
  type: 'engine.error';
  sessionId: string;
  timestamp: number;
  error: string;
}
```

When an STT or TTS provider error crosses the runtime boundary, `engine.error`
still keeps a verbose, human-readable `error` string. Structured provider
metadata is optional and additive, it supplements the message and does not
replace it.

```ts
{
  type: 'engine.error';
  sessionId: string;
  timestamp: number;
  error: string;
  kind?: 'auth' | 'quota' | 'transport' | 'parse' | 'server' | 'unknown';
  source?: 'stt' | 'tts';
  provider?: string;
}
```

Only these six provider kinds are part of the current contract:

| kind | Meaning |
| --- | --- |
| `auth` | Invalid credentials, expired credentials, or permission failures. |
| `quota` | Usage limits, subscription limits, or credit exhaustion. |
| `transport` | Connection loss, websocket failures, timeouts, or other network transport issues. |
| `parse` | Provider payloads that could not be decoded or validated. |
| `server` | Provider-side 5xx or equivalent upstream service failures. |
| `unknown` | Any provider error that does not fit the shared buckets above. |

The same taxonomy is shared by both voice provider boundaries:

- `source: 'stt'` identifies Speech-to-Text provider failures such as rejected credentials, streaming transport problems, or malformed transcript payloads.
- `source: 'tts'` identifies Text-to-Speech provider failures such as rejected credentials, synthesis transport problems, or malformed audio metadata.
- `provider` names the upstream provider when that detail is available.

These fields stay optional. Clients should treat them as extra context on top of
the main message string, not as a guaranteed replacement for it.

## Recommended UI behavior

| kind | Suggested user-facing behavior |
| --- | --- |
| `auth` | Tell the operator credentials are misconfigured; do not ask the end user to retry repeatedly. |
| `quota` | Surface temporary unavailability and route to typed input or a non-voice path. |
| `transport` | Offer retry and keep typed input visible. |
| `parse` | Show a generic voice failure and report diagnostics server-side. |
| `server` | Treat as provider outage or backend failure; retry later. |
| `unknown` | Show a generic recoverable failure and log the full server-side context. |

`sessionId` is part of the demo websocket payload so the client can correlate the event with the active session. Do not copy that field into telemetry attributes unless a telemetry contract explicitly allows it; error payload correlation and privacy-safe telemetry are separate surfaces.

## Demo websocket boundary behavior

The demo server preserves provider-classified runtime errors on `engine.error`
without introducing a new event type. It forwards optional `kind`, `source`, and
`provider` fields only when the runtime error already exposes them. Otherwise,
it sends the legacy string-only payload.

The `engine.error.error` field is a flattened human-readable message string. If a
provider error wraps nested causes, the demo websocket flattens that cause chain
into the serialized message text before sending it to the client.

Raw `cause` objects and stack traces are not serialized over the wire.

That means clients can keep existing message handling and opt into source-specific
narrowing when metadata is present.

```ts
if (error.source === 'stt') {
  console.log('STT provider error', error.kind, error.provider, error.error);
}

if (error.source === 'tts') {
  console.log('TTS provider error', error.kind, error.provider, error.error);
}
```

If `source` is missing, treat the event as a generic voice setup or runtime
failure and fall back to the legacy string-only handling path.
