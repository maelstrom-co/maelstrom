By the end of this tutorial you will speak to the repository demo, watch the UI adapt, and hear the result spoken back. You will run three processes: a local LiveKit server, the STT/TTS worker, and the browser app.

This is a learning checkpoint, not a deployment. The demo mint route is development-only and is not deployable.

## What you need

- The repository cloned, with `bun install` already run.
- Deepgram and Cartesia API keys.
- A `GOOGLE_API_KEY` or `GEMINI_API_KEY` for the Engine.
- A browser with microphone permission.

## Wire the browser adapter

Create one `LiveKitAdapter` for each Maelstrom voice session. The callback that fetches the room grant is application-provided; keep LiveKit signing credentials out of the browser bundle.

```ts title="src/voice/livekit-adapter.ts"
export function createLiveKitAdapter({
  sessionId,
}: CreateAdapterContext): LiveKitAdapter {
  return new LiveKitAdapter({
    roomName: `maelstrom-${sessionId}`,
    mintToken: fetchLiveKitToken,
    thinkingFallbackMs: 10_000,
  });
}
```

During `connect()`, the adapter calls LiveKit's `setMicrophoneEnabled(true)` to acquire and publish the microphone, then `setMicrophoneEnabled(false)` to mute the existing publication until a turn starts. A denied browser permission surfaces as `MIC_PERMISSION_DENIED`; explain how to allow access, then reconnect.

The adapter ignores partial and blank transcription segments. Each non-empty final transcript emits a user transcript event and exactly one synthetic `update_ui` tool call whose `intent` is the trimmed transcript. That natural-language intent follows the normal Maelstrom path; the worker never plans the UI.

## Speak after connection

Automatic browser VAD is the default when you omit `vad`, as in the adapter above. After the session reports automatic turn mode, speak normally. The adapter detects speech, publishes the bounded turn, and signals the worker when speech ends; do not call `turnControl` for this path.

`turnControl` appears only when you intentionally configure `vad: false` or automatic control safely falls back to manual mode. If the UI shows manual mode, use the currently exposed control for one [hold-to-talk interaction](/guides/voice/livekit-cascade/#delimit-each-manual-turn): call `startTurn()` on press and always call `endTurn()` on release or cancellation. Do not cache the control because it can appear or disappear as the connection mode changes.

If a turn produces no final transcript, the provider-specific `thinkingFallbackMs` timer returns the session from `thinking` to `connected`; the configured `10_000` milliseconds bounds that recovery. Set the option to `0` only when another integration owns empty-turn recovery, because disabling it can leave an unanswered empty turn in `thinking`.

## Run the checked-in demo locally

<Aside type="danger" title="Repository demo route is development-only">
  The checked-in demo mint route signs grants without authenticating the caller.
  It exists to make this tutorial runnable. Replace it with the server-owned
  route from the [LiveKit cascade
  guide](/guides/voice/livekit-cascade/#mint-a-room-grant-on-your-server) before
  any deployment.
</Aside>

1. Copy the root `.env.example` to `.env`. Keep the existing `GOOGLE_API_KEY` or `GEMINI_API_KEY` for the Engine, add real `DEEPGRAM_API_KEY` and `CARTESIA_API_KEY` values, and leave the example `LIVEKIT_*` values unchanged.
2. Follow the official [Install LiveKit Server](https://docs.livekit.io/home/self-hosting/local) instructions if the binary is not installed. Then start the local LiveKit process in one terminal:

   ```bash
   livekit-server --dev
   ```

   The `--dev` flag uses well-known insecure `devkey` / `secret` credentials that are suitable only for local development.

3. From the repository root, start the full demo in another terminal:

   ```bash
   bunx nx dev-livekit demo
   ```

   The Nx target starts the Engine host, the long-running STT/TTS worker, and the browser app. The separate `livekit-server --dev` command supplies the local LiveKit process.

## Verify

Open [http://localhost:3000](http://localhost:3000), connect voice, wait for automatic turn mode, and speak. If the UI instead shows manual mode, hold to talk and release. A final transcript should become ordinary intent; after the UI settles, the worker should speak the result.
