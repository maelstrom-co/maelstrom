Maelstrom is open source, and the first public release, **0.1.0**, is available
on npm.

Maelstrom lets a model arrange your application's components, select their
states, and invoke the actions you expose. Your code owns the components,
application data, authorization, and effects.

The overview illustrates the runtime flow: the client sends intent and current
UI state to the Engine, then applies the returned layout before running actions.
The [sound-effects license](https://github.com/maelstrom-co/maelstrom/blob/main/media/maelstrom-overview.LICENSE) is included in the repository.

## Start with one capability

For an existing app, choose one useful workflow and identify the components it
needs. Declare their available states and actions as Vessels, then connect the
client to an Engine. Keep the first integration small enough to verify against
the behavior your application already supports.

For a new app, the [React starter](https://docs.maelstrom-ai.co/getting-started/starter/)
runs locally without a provider key. Its deterministic planner verifies the
client-to-Engine path; it does not call a model. Connect a selected model planner
when you are ready to test model decisions.

The [Maelstrom skill](https://docs.maelstrom-ai.co/agents/skills/) asks about your
goal and starting point, then routes to the existing workflow for that task.
The [standalone prompts](https://docs.maelstrom-ai.co/agents/prompts/) are also
available when you prefer a copyable instruction without installing skills.

## Install the public SDK

```sh
npm install @maelstrom-co/react
```

No GitHub token or repository invitation is required. Use matching Maelstrom
package versions. The [installation guide](https://docs.maelstrom-ai.co/getting-started/installation/)
explains the browser and server packages.

The SDK uses the MIT license. It is still in the 0.x series, so read the
[release notes](https://github.com/maelstrom-co/maelstrom/releases/tag/v0.1.0)
before upgrading.
