We kept building AI features and coming back to the same frustration. A model
could understand what someone wanted, but the interface still made them find
the right screen and do each step themselves.

We'd spent years learning how to make software easier to use. A calendar can
make a busy week easier to understand because someone made choices about what
matters and how to show it. That knowledge should still shape how AI works
inside an app.

With Maelstrom, you build the components and decide what they can do. The
framework lets a model arrange them around the user's task and run the actions
you've made available.

Maelstrom is now open source under the MIT license. Our first public release,
0.1.0, is available, and you can explore the [code on GitHub](https://github.com/maelstrom-co/maelstrom).

## An interface that follows the task

Imagine someone planning their week. They ask to see their tasks beside their
calendar, then ask to add a task. Maelstrom can bring those components into view
and run the task list's add action. They can still click and type in the app.

As their focus changes, the model can change the arrangement. The components
keep the design and behavior your team gave them. You decide how each can
appear and which actions it offers.

This is the kind of interaction we're building Maelstrom for: dashboards and
workspaces where the useful view changes with the task.

## Try it in your app

If you already have an app, start with our [guided setup](/#get-started).
Copy the integration prompt into your coding agent. It asks what you want to
build, looks at your project, and helps you plan a small first integration.
You review the plan before making changes.

Our [Maelstrom skills](https://docs.maelstrom-ai.co/agents/skills/) give your
coding agent guidance for setup and later development tasks. The entry skill
asks whether you're starting fresh or working in an existing app.

For a new project, [clone and run the React starter](https://github.com/maelstrom-co/react-starter#run).
It includes a working app and local server. It starts with a fixed greeting
response, so you can run it without a model API key. The guide explains how
to connect a model when you're ready.
