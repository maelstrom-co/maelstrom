# Jev 1.14.0 against Jev 1.13.0 for the planner, light tier and router

Ticket: ClickUp MAE-960 "Jev 1.14.0 against Jev 1.13.0 for the planner, light tier and router"
(https://app.clickup.com/t/123nktjydah). Research date: 2026-11-08. Follows up
`docs/research/jev-replacement-candidates.md` (MAE-958), which put this comparison ahead of any
switch to another provider.

Every number below was measured on 2026-11-08, with both models run against the same sets. Round 1
ran 1.13.0 first. Round 2 swapped the order. Every claim carries a source. Raw artifacts live under
`docs/research/jev-1-14-vs-1-13/` and paths below are relative to that directory.

## Recommendation

Keep the pin at `jev-1.13.0`. A confirmation rerun with swapped order reproduced a small planner
regression on 1.14.0. Pass and cheap correct are lower in both rounds. The combined paired McNemar
p is 0.078 for pass and 0.066 for cheap correct. That is suggestive, not significant at 0.05, and
consistent in direction across rounds. The bar for this pin is no regression, so we hold. The light
tier and the router tie. There is no latency gain. Revisit on a 1.13.0 sunset notice or a concrete
need for `box` or multilingual support, and re-benchmark then. Any Jev replacement benchmark
(ClickUp "Jev replacement candidates for the light tier and router",
https://app.clickup.com/t/123nktjyda6) should compare against 1.13.0. Nothing should use
`jev-latest`, because it points at 1.14.0.

Decision rule, set before round 2: hold the pin if 1.14.0 again trails on both overall pass and
cheap correct, or if the combined paired McNemar favors 1.13.0 with p < 0.1. Both conditions
triggered.

Sources: tables below. Alias: https://docs.typesafe.ai/models.md.

## Question

Does TypeSafe `jev-1.14.0` match or beat our pinned `jev-1.13.0` on accuracy and latency for
three things: the planner stages, the light tier's multi-question pick and the router's route
choice? Can we move the pin?

## Method

Same machine, same API key. For each set, 1.13.0 and 1.14.0 ran back to back or
interleaved. Times are CET.

Round 2 timestamps: the request gave 1.14.0 as local times and 1.13.0 as `Z` times. They are
consistent. `meta.date` in `summary.json` is UTC and records the end of each run: 1.14.0 round 2
10:36:20Z (11:36:20 CET) and 1.13.0 round 2 10:58:43Z (11:58:43 CET). The 1.13.0 start of 10:37:08Z
is 11:37:08 CET. Round 2 was run on the same day as round 1, so day to day variance is still not
measured.

| Planner (MAE-832), round 1 | `packages/evals`, suite `all`, arm `jev-poc`, 155 scenarios x 3 repeats, concurrency 1, fallback LLM `gpt-5.6-luna` | `b5df54cc` | 465 runs, 408 scored | 1.13.0 08:40 to 09:04, 1.14.0 09:05 to 09:28 |

The router ran 1.13.0 twice, with 1.14.0 in between. This shows the run to run noise of 1.13.0

## Changelog facts

Primary sources: https://docs.typesafe.ai/changelog.md, https://docs.typesafe.ai/models.md,
https://docs.typesafe.ai/api/system-one.md. Read 2026-11-08.

- 1.14.0 was released October 14, 2026 (changelog). The entry reads "Better multilingual
  support." and adds the `box` question type ("Box questions need Jev 1.14.").
- The changelog states no change to choice scoring, latency or the reply schema.
- Price is the same for both: $0.042 per 1M input tokens, output free (models.md).
- Image input and opt-in long context (262k with header `TypeSafe-Danger-Zone-Long-Context: true`,
  default 64k per request and 32k per question) work on both 1.13 and 1.14, so they are not new.
  Images and `box` need header `TypeSafe-Danger-Zone-Images: true` (system-one.md).
- `jev-latest` points to `jev-1.14.0`. So does `jev-preview` (models.md).
- The "60 days notice before 1.13.0 deprecation" claim is not in the primary docs. models.md says
  there is no deprecation policy and no sunset dates. Only secondary sources (for example
  remio.ai) repeat it, and it is unverified. We do not rely on it.
- The response `model` field "may differ from the alias supplied in the request" (system-one.md).
  Our client asserts that the echo matches the pin, so an alias would trip that check.

## Caveats

- All runs are on 2026-11-08. The planner ran in two rounds, the second with swapped order. No day
  to day variance is measured.
- API latency drifts. The earlier 1.13.0 light tier capture
  (`apps/demo/prototype-mae826/results/light-tier-eval.txt` on the prototype branch) had p50 248
  ms. Today's 1.13.0 p50 is 184 to 197 ms. Compare latency only within this session.
- Router labels were written from the product's route descriptions. They are not validated
  against the live loop. 5 clear `ui_only` cases paraphrase the description's own examples, which
  may flatter both models. Journey logs (11 turns, all `needs_tools`, no request text) could not
  be replayed, hence the labeled set. The set is small (33 cases).
- The light tier harness lives on the prototype branch `ktrz/composed-planner-prototype`, not on
  `main`.
- The "cheap correct" metric (pass with zero fallback) is the main planner signal for Jev. The
  fallback LLM adds its own noise to the plain pass rate, because a fallback run can pass or fail
  on the LLM alone. Cheap correct was lower for 1.14.0 in both rounds (171 and 169 against 179 and
  179). Fallback runs were about equal (219 to 223).
- The planner gap is suggestive, not significant at 0.05 (combined p 0.078 and 0.066). It is
  consistent in direction across both rounds. The human's bar is no regression, so it decides the
  pin.

## Reproduce

Planner eval (run per model, from the repo root at commit `b5df54cc`). Round 2 used the same
command with `--out tmp/evals/jev-1.13.0-round2` and `--out tmp/evals/jev-1.14.0-round2`, 1.14.0 first.

```
NX_NO_CLOUD=true JEV_MODEL=jev-1.13.0 bunx nx run @maelstrom-co/evals:eval -- --suite all --arm jev-poc --repeats 3 --out tmp/evals/jev-1.13.0
NX_NO_CLOUD=true JEV_MODEL=jev-1.14.0 bunx nx run @maelstrom-co/evals:eval -- --suite all --arm jev-poc --repeats 3 --out tmp/evals/jev-1.14.0
```

Light tier: from a worktree of branch `ktrz/composed-planner-prototype` @ `febb0912` with `.env`
copied in. Swap the model id for `jev-1.13.0`, run the two models interleaved, 3 repeats each.

```
JEV_MODEL=jev-1.14.0 bun --conditions=@maelstrom-co/source --env-file=.env apps/demo/prototype-mae826/composed-planner-eval.ts
```

Router: from the root of this branch. Same command with `--model jev-1.13.0` for the other model.

```
bun --env-file=.env docs/research/jev-1-14-vs-1-13/router-replay.ts --model jev-1.14.0 --repeats 3 --out docs/research/jev-1-14-vs-1-13/raw/router-jev-1.14.0.json
```

Paired statistics, from this worktree root, reading only the four `records.json` files:

```
python3 -I docs/research/jev-1-14-vs-1-13/paired.py
```

Any run without `--dry-run` sends real requests. All steps need `TYPESAFE_API_KEY` in `.env`.
